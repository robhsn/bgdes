Upstream decisions

Resolve these first to unblock screens

Each of these decisions sits above multiple screens. Locking them in before starting the wireframes will save reworking later.

  1. App-open state — dedicated lobby vs default-to-board. Blocks: 01 (landing), 11 (game-start), 10 (connecting context)
  2. Auth gate model — anonymous-first with later promotion (like web), or forced registration. Blocks: 05–07 (auth flow order), 08 (whether tutorial requires registered user)
  3. Generic modal/menu pattern — centered alert vs bottom sheet/drawer. Blocks: 03 (system actions), 11 (game-start surface), 13 (in-game settings), 14 (match-end)
  4. Responsiveness scope — only the 3 FTUE tutorial-adjacent tickets explicitly call out portrait-only + iPhone/iPad. The 5 other tickets are silent. Worth confirming whether the same constraint applies project-wide before sizing.
